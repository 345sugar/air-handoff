# AIR HANDOFF

**空のバトンを、次の管制官へ。**

ベテラン管制官の「なぜ、そう判断したか」を言葉にし、次の世代の学びにつなぐAI教育支援プロジェクトです。既存の成田管制塔シミュレーターを土台に、AIの提案と人の判断の差分を記録し、理由・解説・練習課題へ変える仕組みを作ります。

## 何を解決するか

管制の無線に残るのは指示であり、判断の理由は残りにくい。風、視程、距離、滑走距離、交信のテンポなどをどう組み合わせて判断したかが、ベテラン個人の経験の中にとどまっています。

AIR HANDOFFは、ベテランが添える一言を記録し、振り返りと新人教育に使える形にします。

1. **ベテランからAIへ**：同じ場面に対するAI案と実際の指示を比べ、違いと理由を残す。
2. **AIから新人へ**：確認・承認された判断をもとに、問い、解説、練習課題を作る。
3. **新人からベテランへ**：新人が迷う場面を集計し、教え方の改善につなげる（追加目標）。

## Hackathonで実装するMVP

「教える → 残す → 教材にする」の一周を、シミュレーター上で動かします。以下はすべて**実装予定**です。

- [ ] **AIの提案と根拠**：複数の指示候補を生成し、生成とは独立したシミュレーター／採点器で比較する。ゲーム内の安全間隔条件に違反する候補は除外し、残った候補から提案と根拠1行を表示する。
- [ ] **判断の差分**：ベテランがシミュレーター上で出した指示を記録し、AI案と異なる場合に並べて表示する。
- [ ] **理由の構造化**：差分に理由を1行添え、風・視程・距離・滑走距離・交信などの要素タグに整理して保存する。
- [ ] **判断ログと承認**：時刻・場面・AI案・実際の指示・理由・タグ・承認状態を一覧で確認できるようにする。教材に使う判断は確認・承認したものに限定する。
- [ ] **訓練生モード**：保存した場面を再現して指示を問う。回答を同じ採点器で検証し、条件を満たす回答をベテランの判断と比較する。
- [ ] **解説と反復練習**：見落とした条件と次に変えることを説明し、条件を1つずつ変えた練習課題を3本生成する。

Claudeには、候補生成、理由の整理、解説、練習課題の生成を担わせる予定です。採点器は生成結果を検証する役割として分けます。使用モデル、API連携方式、採点指標、保存形式は実装時に追記します。

### 余力があれば取り組むこと

- 蓄積した判断を参照し、同じ場面でのAI提案・説明を改善する。
- 2人目のベテランによる確認と、意見が分かれた判断の再検討に対応する。
- 新人のつまずきを集計し、ベテランへ返す。

## デモで扱う場面

舞台は **成田RWY16R**。出発機がA2で待機し、到着機は6 NM、向かい風20 kt、視程良好という架空の条件で、**「到着機の前に出すか、降りてから出すか」**を扱います。

1. 同じ場面を見たAIが、検証済みの候補と根拠を提示する。
2. ベテランが指示を選び、AI案との差分に理由を添える。
3. 理由と条件をログとして保存し、確認・承認する。
4. 訓練生がその場面に回答し、判定と理由の説明を受け取る。
5. 条件を1つ変えた課題で、もう一度判断する。

この一連の動作をHackathonの成果として示す予定です。動画ページの **4:24「顔① ベテランの隣で」／4:59「デモ画面」／6:19「顔② 新人を教える」** で構想を紹介しています。

## 対象範囲

対象は、滑走路とその周辺を扱う管制塔の判断を題材にしたシミュレーションと教育支援です。実際の管制席には接続せず、実機への指示や管制の自動化は行いません。

シナリオには公開情報と架空のコールサイン・数値を使い、非公開資料・機密情報は扱いません。ゲーム内の判定は実運航の安全性や訓練資格を保証するものではなく、既存シナリオも未監修です。
